# projects/ — клиентские проекты студии

Каждый проект — отдельная папка с латинским именем (slug). Внутри: документы цепочки агентов, привязки к Figma, журнал изменений.

## Жёсткие правила этой папки

1. **Один проект = одна папка.** Имя папки — slug (латиницей, через дефис, в нижнем регистре).
2. **Каждая папка проекта содержит свой `CLAUDE.md`** с правилами именно этого проекта (стек, особенности клиента, региональные требования).
3. **Каждая папка проекта содержит `figma-binding.md`** — привязка к конкретному Figma-файлу клиента.
4. **Каждая папка проекта содержит `CHANGELOG.md`** — журнал крупных изменений.
5. **Не редактировать чужие проекты** без понимания контекста. Не путать данные клиентов.

## Структура папки проекта

```
projects/<slug>/
├── CLAUDE.md                        ← правила этого проекта
├── figma-binding.md                 ← привязка к Figma
├── CHANGELOG.md                     ← журнал изменений
│
├── 00-intake.md                     ← результат секретаря
├── 01-brief.md / 01-brief-review.md ← бриф или его ревизия
├── 02-personas.md / 02-personas-review.md
├── 03-moodboard.md / 03-moodboard-review.md
├── 04-ui-kit-spec.md / 04-ui-kit-review.md
├── 05-ui-kit-inventory.md           ← индекс компонентов с привязкой к Figma node ID
│
└── (по мере роста)
    ├── 06-layouts/                  ← макеты экранов (когда дойдём)
    ├── 07-content/                  ← UX-копирайт
    └── 08-frontend/                 ← код фронтенда (или отдельный репо)
```

## Правила нумерации файлов

- **00-09 — исследование и проектирование** (intake, бриф, персоны, мудборд, UI-kit)
- **10-19 — макеты и контент** (layouts, content)
- **20-29 — разработка** (frontend, backend)
- **30-39 — запуск и поддержка** (deploy, CMS, QA, legal)

Это позволяет видеть прогресс проекта по списку файлов в папке.

## Правила для CLAUDE.md проекта

В CLAUDE.md проекта обязательно:
- Имя проекта и slug
- Тип клиента
- Текущий статус (на каком этапе цепочки)
- Технические рамки (регион работы, языки, админка)
- Ссылка на главный Figma-файл
- Особенности этого проекта (что нестандартного по сравнению с шаблоном)
- Lessons learned именно этого проекта

## Жизненный цикл проекта

1. **Запуск.** Дарья создаёт папку через secretary → `00-intake.md`.
2. **Цепочка агентов.** По одному документу за запуск. Каждый — отдельный коммит.
3. **Итерации.** Документы могут пересоздаваться (-review.md, потом обновлённый основной).
4. **Завершение проекта.** Папка фиксируется, в `CHANGELOG.md` — финальная запись «Проект сдан».
5. **Архив.** Завершённые проекты остаются в `projects/` как часть портфолио студии.

## Что НЕ делать

- Не складывать сюда «черновики» и «временные файлы». Всё должно иметь место в структуре.
- Не дублировать данные между проектами. Если что-то общее — выносить в `.claude/skills/`.
- Не редактировать `00-intake.md` после того, как секретарь его создал, кроме как через журнал и редкие правки маршрута. Это исторический документ.
