## Стратегические решения проекта

### Решение 1 (2026-05-18): Вариант A по характеру

В мудборде выявлено расхождение «зрелый бриф vs дерзкий UI-kit». Решено: **визуал не меняем, «зрелость» закрывается контентом** (кейсы с цифрами, логотипы брендов-клиентов на первом скролле, блок гарантий).

**Гипотеза, требует проверки:** коридорное тестирование на 3-5 представителях персоны Елена (B2B-CMO 30–40 лет).

См. `03-moodboard-review.md`, раздел 9.

### Решение 2 (2026-05-18): Блокеры до layout-designer

Из ревизии UI-kit зафиксированы критические блокеры. До запуска `layout-designer`:

- [ ] Создать Figma Variables (палитра + типографика + spacing). Сейчас `get_variable_defs` возвращает `{}`.
- [ ] Дорисовать `Navigation/Mobile` + `Hamburger Menu` (Максим — mobile-first).
- [ ] Дорисовать `Role Switcher` («Для брендов / Для блогеров») — центральный элемент архитектуры.
- [ ] Добавить `Focus`-состояния к кнопкам (WCAG 2.4.7).
- [ ] Создать `Stats Block` (для Елены, первый скролл).

См. `04-ui-kit-review.md`, разделы 8-9.

## Технический стек проекта (предварительно)

> Финальный стек определит `frontend-engineer` после `layout-designer`.

- **Frontend:** React + Next.js 14 (App Router) + TypeScript
- **Styling:** CSS Modules (BEM-конвенция) + Tailwind для утилит
- **Анимации:** GSAP или Framer Motion (бриф упоминает Motion + Scrollytelling)
- **CMS:** Strapi 5 (self-hosted) — для админ-панели контента
- **Платежи:** ЮKassa (если будет монетизация — не определено)
- **Хостинг:** Selectel или Timeweb (РФ)

## Особенности проекта

### Архитектура с развилкой
Сайт имеет ключевую развилку «Для брендов / Для блогеров» сразу после Hero. Это центральный паттерн UX — две параллельные ветки контента под две персоны. Это влияет на:
- Навигацию (нужно показывать текущую ветку)
- Footer (формы для каждой ветки разные)
- Аналитику (нужно отслеживать ветку пользователя)

### Кириллица
Шрифт `Unbounded` имеет кириллицу, но требует проверки рендера в Bold/Black начертаниях на «Щ», «Ъ», «Ю», «Я». Проверить в Chrome 130+ и Firefox 130+ на Windows и macOS до финальной сборки.

### Telegram как канал лидов
Персона Елена работает в Telegram (5/5 по технологиям). Бриф предполагает Telegram-форму или интеграцию TG-бота для B2B-лидов. В UI-kit пока не предусмотрено.

## Lessons learned именно этого проекта

- **2026-05-18 —** Учебный проект «Практика» оказался гораздо более проработанным, чем казалось вначале: 67-слайдовый бриф + детальные персоны + готовый UI-kit. Этапы 2-4 (бриф/персоны/мудборд create) пропущены, мы сразу пошли в режим review.
  - **Почему:** Дарья при описании проекта в первом разговоре не упомянула, насколько глубоко уже проработаны материалы.
  - **Правило:** в `secretary` v3 явно прописан Шаг 6 «Проверка через MCP — оценка качества» с заметками. Это помогает избежать ситуации «думали, что начинаем с нуля, а тут уже почти всё готово».

- **2026-05-18 —** UI-kit «Фундамент v1.0» содержал в спецификации 39 компонентов, но реально собранных Figma Components было ~15. Остальные — текстовый список.
  - **Почему:** при создании UI-kit Дарья описала будущие компоненты, не успев их нарисовать. Документация и реальность разошлись.
  - **Правило:** для UI-kit Nfluence — `05-ui-kit-inventory.md` ведётся как реальный список того, что есть в Figma, с явным статусом по каждому компоненту.
