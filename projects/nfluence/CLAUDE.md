## Ключевые стратегические решения

### Решение 1: Двуветочная эстетика (Вариант B) ⭐

**Зафиксировано:** 2026-05-18 устно, подтверждено 2026-05-22

**Суть:** конфликт «зрелый бриф vs дерзкий UI-kit», обнаруженный sanity-check секретаря, решается через **разделение сайта на две визуальные ветки**.

**Это не два сайта**, а **две визуальные зоны одного сайта**, разделённые через **Role Switcher** на втором экране после Hero:

| Ветка | Аудитория | Палитра | Тон |
|-------|-----------|---------|-----|
| **Тёмная** | Блогеры (Максим) | `Nfl_bg/primary #070809`, `Nfl_accent/lime #C5EE5B` | Дерзкий, хайповый, мобайл-трендовый |
| **Светлая** | Бренды (Елена) | `Nfl_bg/primary-light #F5F4F0` (гипотеза), `Nfl_text/primary-light #0F1A2E` (гипотеза), `Nfl_accent/blue #2D6BFF` (гипотеза) | Структурированный, доверительный, бизнес-ориентированный |

**Общие компоненты обеих веток:** Navigation, Footer, Form-логика, FAQ, Hero (с переключаемым визуалом).

**Специфичные компоненты:**
- Светлая: pill-кнопки, плотный текст с цифрами, инфографика
- Тёмная: курсив-акценты Lora, marquee, drag-карусели, стикерные SVG

### Что это означает для пайплайна

**Для всех будущих агентов:**
- `design-system-architect` — Variables должны включать **обе ветки** или один Color collection с двумя modes (Dark / Light). Не делать «только тёмную, потом подумаем».
- `layout-designer` (когда создан) — макеты обоих веток как одна структура с разными визуалами по секциям.
- `frontend-engineer` (когда создан) — реализация через CSS variables с переключением темы при выборе ветки.

## Следующие шаги

### Приоритет 1 — Светлая ветка Variables (двуветочность)

Сейчас в Figma только тёмная ветка. Чтобы реализовать двуветочную эстетику, нужно либо:

**Вариант 1A.** Добавить mode "Light" в существующий `Color` collection. Тогда `Nfl_bg/primary` имеет два значения — `#070809` в Dark и `#F5F4F0` в Light. Компоненты автоматически переключаются.

**Вариант 1B.** Добавить отдельные переменные с суффиксом `-light`. Тогда `Nfl_bg/primary` остаётся тёмным, а для светлой ветки есть `Nfl_bg/primary-light`. Компоненты привязываются явно.

Решение принимать вместе с Дарьей.

### Приоритет 2 — Role Switcher

Без него двуветочность не работает практически — пользователь не знает, как переключиться. Это **компонент-разводная стрелка** UX.

Спецификация: см. `SPEC-role-switcher.md` (если был создан в предыдущей сессии).

### Приоритет 3 — Лейаут UI-kit на странице Figma

Дарья 2026-05-22: «лейаут самого UI-kit в Figma — как лежат элементы на холсте — не нравится».

Это про **визуальную организацию страницы Figma** (где какие секции, отступы между ними), **не про дизайн компонентов**. Требует скриншота + обсуждения с Дарьей.

### Приоритет 4 — Удалить неиспользуемое из UI-kit

Из ревизии 2026-05-18: заявлено 39 компонентов, реально собрано ~15. Текстовые секции «документация» без реальных компонентов — можно удалить или вынести в отдельный архивный фрейм.

### Приоритет 5 — Остальные блокеры для layout

- Привязка существующих компонентов к Variables (через BIND-режим DS-architect)
- Создание новых компонентов: Form ×2 (Бренд / Блогер), Process/Timeline, Stats Block, Footer (если ещё нет)
- Focus-состояния у кнопок (WCAG 2.4.7)

## Особенности проекта

- **Figma-файл «Практика»** — учебный, содержит несколько проектов. Поэтому префикс `Nfl_` для всех Variables обязателен.
- **Кириллица** — все шрифты должны её поддерживать. Подтверждены: Unbounded (ok), Onest (ok), Lora включая Italic (ok, Cyreal-приоритет).
- **Mobile-first** — Максим всегда с телефона. Mobile-варианты компонентов обязательны.
- **Юридический фокус** — секция «Маркировка / закрывающие документы» для Елены критическая. Не упрощать в копирайте.
