## 1. Что сильно

- **Архитектура двуветочная и явная** — Router «Для брендов / Для блогеров» как второй экран после Hero — правильное решение, закрывает обе персоны без смешения.
- **USM полноценная** — 6 этапов (Узнать → Выбрать роль → Выгода → Формат → Примеры → Целевое действие) с отдельными строками для каждой персоны. Логика линейная и проверяемая.
- **User Story детальные** — по 4 истории на персону, сформулированы как «Как [роль], я хочу [действие], чтобы [результат]». Конкретны и операциональны.
- **Контекстное поведение** — устройство, паттерн поиска, триггеры, реакция на контент — всё задано явно и по-разному для каждой персоны.
- **Архитектура 13 секций** — полная, с разделением потоков (7 секций для блогеров, 6 для брендов + общие). Параллельная структура.

## 3. Тест «персоны конфликтуют»

| Критерий | Елена | Максим | Конфликт? |

| Контекст | Desktop, офис, 3–5 мин рабочего времени | Mobile, на бегу, секунды для первой оценки | ✅ разные |

**Вывод: персоны конфликтуют по всем ключевым параметрам.** Это не дублирование — это два разных дизайн-режима в рамках одного сайта. Правильно.

Следствие для дизайна: компоненты, которые работают для Максима (крупная яркая кнопка «Стать блогером», дерзкая типографика, видео-фон), отчасти работают против Елены — и наоборот (плотный текст с цифрами, «скучный» для Максима блок). Router-развилка на втором экране — единственное корректное решение.

## 4. Тест «можно принять дизайн-решение»

### По Елене:
- **Типографика:** читаемая, без декоративных излишеств. Второй шрифт (Onest) — основная рабочая лошадь для текста, не Unbounded. Размер тела — 16–18px.
- **Длина текста:** длинная допустима — она читает 3–5 мин. Инфографика и таблицы лучше сплошного текста.
- **CTA:** «Обсудить проект» или «Скачать презентацию» — НЕ «Позвоните нам». Форма, не звонок.
- **Desktop приоритет:** да. Но адаптация мобайла нужна — командировки и совещания.

### По Максиму:
- **Типографика:** дерзкая, крупная, Unbounded как основной акцент. Тело — короткое, сканируемое.
- **Длина текста:** минимальная. Буллеты, иконки, визуальные карточки — не лонгриды.
- **CTA:** «Стать блогером Nfluence» — яркий, большой, заметный с первого скролла. Кнопка должна бросаться в глаза.
- **Mobile first:** обязательно. Если сайт не адаптирован — уходит немедленно.

**Вывод: по обеим персонам дизайн-решения выводятся без домысливания.** Это качественные персоны.

## 8. Критические пробелы

1. **Role Switcher не создан** — это центральный компонент ИА (второй экран). Без него сайт не работает для обеих персон одновременно. Приоритет #1 для design-system-architect.

2. **Form × 2 не создана** — форма «Обсудить проект» (для Елены) и форма «Стать блогером» (для Максима) — два разных компонента с разными полями. Приоритет #2.

3. **Мобайл User Flow не детализирован** — Максим всегда на телефоне, но отдельного мобайл-флоу нет. При разработке layout-designer это нужно будет добавить.

4. **Edge cases не описаны** — что делает пользователь, если не готов к решению? Нет «нейтрального» пути (просто читаю, пока не конвертируюсь). USM линейная, но реальное поведение нелинейно.

---

## 9. Рекомендации

1. **Role Switcher — приоритет** в задании design-system-architect. Это не декоративный компонент, это UX-разводная стрелка.

2. **Для moodboard EXTRACT:** явно указать куратору — каждый референс должен ответить на вопрос «как это работает для Максима и как — для Елены». Не просто «извлечь палитру».

3. **Тарифы / пакеты** упомянуты в ИА (секция «Условия сотрудничества»), но нигде не определены по содержанию. До layout это нужно прояснить с Дарьей.
