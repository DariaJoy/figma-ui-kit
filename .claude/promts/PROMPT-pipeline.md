# Промт-конвейер: автозапуск цепочки агентов до готового UI-kit

## Зачем

Один длинный промт, который ведёт проект через всю цепочку **автоматически**, с минимальным участием Дарьи. Сценарий: «новый клиент → готовый UI-kit в Figma + Variables + базовые компоненты».

## Когда использовать

- Новый проект студии
- Перезапуск существующего проекта на чистую
- Учебный прогон цепочки

## Перед запуском — обязательно

1. **Бэкап Figma-файла** клиента (File → Save local copy + Duplicate в облаке)
2. **Файл открыт в Figma Desktop** (не в браузере)
3. **Новая сессия Claude Code** (не продолжение старой)
4. **Все .md файлы агентов на месте** в `.claude/agents/`

ПРАВИЛА АВТОПРОГОНА:

1. Работаешь ПО ЦЕПОЧКЕ: secretary → brief-analyst → ux-researcher →
   moodboard-curator (EXTRACT) → design-system-architect (CREATE-FROM-EXTRACT) → СТОП.

2. На каждом шаге:
   - Перечитываешь свой .md файл из .claude/agents/<имя>.md
   - Делаешь работу в указанном режиме
   - Записываешь результат в projects/<slug>/<NN-имя>.md
   - В конце шага коротко сообщаешь: «Готово: <файл>. Перехожу к <следующий>».
   - НЕ останавливаешься, продолжай сразу к следующему агенту

3. Останавливаешься и спрашиваешь Дарью ТОЛЬКО в этих случаях:
   - Нужны входные данные, которых нет в этом промте
   - Стратегическое противоречие (например, бриф vs референсы)
   - Перед write-операциями в Figma (создание Variables, компонентов)
   - Перед привязкой существующих компонентов к новым Variables (риск)

4. Не делай дублирующих вызовов MCP. Если уже читал бриф через get_metadata —
   не читай снова, используй ранее полученные данные. Контекст-окно у тебя есть.

5. Используй язык русский для документов и общения.

6. По умолчанию режимы агентов:
   - secretary: intake
   - brief-analyst: review (если бриф есть в Figma) или create
   - ux-researcher: review (если персоны есть в Figma) или create
   - moodboard-curator: EXTRACT (главный режим, извлекаешь стиль с указанных URL)
   - design-system-architect: CREATE-FROM-EXTRACT (главный режим)

7. Финальная остановка — после design-system-architect (CREATE-FROM-EXTRACT).
   Не запускай layout-designer (этот агент пока не существует).

## Что произойдёт после запуска

Claude последовательно:

1. **Прочитает входные данные** из промта
2. **Запустит секретаря** — intake, sanity-check
3. **Перейдёт к brief-analyst** — ревизия брифа в Figma
4. **Перейдёт к ux-researcher** — ревизия персон
5. **Запустит moodboard-curator в режиме extract** — откроет ваши референсные URL, извлечёт палитру, шрифты, паттерны
6. **Спросит подтверждение перед write** в Figma (бэкап, файл открыт)
7. **Создаст Variables** через use_figma
8. **Создаст базовые компоненты** (Button, Card, Section Header) привязанные к Variables
9. **Спросит подтверждение** на привязку существующих компонентов
10. **Финал** — отчёт о созданном

## Что я заложил в безопасность

- **Остановки перед рискованными операциями** (write в Figma, привязка существующих)
- **Атомарность скриптов** (упал = ничего не создалось)
- **Проверка через `get_variable_defs`** и `get_metadata` после каждого write-этапа
- **Не запускает несуществующих агентов** (layout-designer не пробуется)

## Что прислать сюда после прогона

- Финальный отчёт Claude
- Скриншот панели Variables в Figma
- Файл `03-moodboard-extracted.md` (это новый файл и он критичен — посмотрим, насколько хорошо извлёкся стиль)

## Если что-то пошло не так

- На любом этапе можно нажать ESC в Claude Code, чтобы прервать
- Откат: Ctrl+Z в Figma Desktop откатывает use_figma операции
- В крайнем случае — восстановление из бэкапа
