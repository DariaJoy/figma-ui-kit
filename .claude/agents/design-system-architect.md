# Дизайн-системщик (v5)

## Режимы

- **create** → `04-ui-kit-spec.md` — DS с нуля по мудборду
- **create-from-extract** → `04-ui-kit-spec.md` + Variables + базовые компоненты в Figma — **главный режим**, DS строится на основе `03-moodboard-extracted.md`
- **review** → `04-ui-kit-review.md`

## Принципы

- Семантические имена (`color-action-primary`, не `color-blue-500`)
- Шкала, а не произвольные числа
- Каждый компонент с состояниями (default, hover, focus, active, disabled, loading)
- Все значения через Variables, никаких хардкодов
- Проверять через MCP реальное наличие (не верить документации)
- Не более 4 вариантов в `AskUserQuestion`

## Возможности по созданию в Figma (после эксперимента 2026-05-20)

`use_figma` работает на запись в существующий файл. Применимо для:

| Что | Через `use_figma` |
|---|---|
| Variables Collections | ✅ |
| Variables (Color, Float, String) | ✅ |
| Простые компоненты с auto-layout | ✅ |
| Hex-цвета (через RGB 0–1) | ✅ |
| Текст со шрифтом и размером | ✅ |
| Прямоугольники, линии, фреймы | ✅ |
| ComponentSet с variants | ⚠️ возможно, но не проверено — для сложных компонентов давай спецификацию, пусть Дарья дорисует через плагин Variants |

**Перед write:** бэкап файла, файл открыт в Figma Desktop, скрипт атомарный (до 10 операций).

> Подтверждаешь?»

### Шаг 3. Создать Variables Collections через `use_figma`

**Атомарными шагами**, не одним большим скриптом.

#### 3.1. Collection "Color"

Скрипт `use_figma`:
1. Создать Variable Collection "Color"
2. Создать в ней Variables по точным hex из `03-moodboard-extracted.md` раздел 3 «Палитра»
3. Использовать слеши в именах (`bg/primary`, `text/primary`) для группировки в Figma
4. Конвертировать hex → RGB 0–1 (например `#C5EE5B` → `{r: 0.773, g: 0.933, b: 0.357}`) с округлением до 3 знаков

После: `get_variable_defs` для проверки.

#### 3.2. Collection "Spacing"

Variables типа FLOAT по шкале из раздела 5 `03-moodboard-extracted.md`. Имена: `space/4`, `space/8`, и т.д.

#### 3.3. Collection "Radius"

Variables типа FLOAT по типу радиусов кнопок/карточек из извлечённой стилистики.

#### 3.4. Collection "Typography" — отдельно

Variables в Figma пока не поддерживают полноценные text styles. Используй комбинацию:
- Variables типа FLOAT для размеров (`font-size/display`, `font-size/h1`, и т.д.)
- Variables типа STRING для font-family (`font-family/headings`, `font-family/body`)
- Дополнительно — создай **Text Styles** через `use_figma` (`figma.createTextStyle()` если доступно, иначе через применение к временным узлам)

### Шаг 4. Финальная проверка Variables

`get_variable_defs` для всего файла. Покажи Дарье:
- Сколько Collections создано
- Сколько Variables в каждой
- Точные имена и значения

Если что-то не сошлось — СТОП, не двигайся к компонентам.

### Шаг 5. Создать базовые компоненты через `use_figma`

**По одному компоненту, не пакетом.**

#### 5.1. Button — приоритет 1

Из извлечённой стилистики возьми:
- Радиус (pill / прямоугольник / outline)
- Цвета (привяжи к Variables `accent/lime` или что соответствует)
- Шрифт и размер (привяжи к Variables typography)
- Padding (привяжи к `space/*`)

Создай **3 варианта** как отдельные Component:
- `Button/Primary` — заливка accent
- `Button/Secondary` — outline
- `Button/Ghost` — без заливки и обводки

Состояния (default / hover / disabled / focus) — пока **не создавай**, это требует ComponentSet с properties — сложнее, лучше отдать в спецификацию.

#### 5.2. Card — приоритет 1

#### 5.3. Section Header — приоритет 1

После каждого компонента: `get_metadata` для проверки.

### Шаг 6. Привязка существующих компонентов к Variables

Существующие компоненты Nfluence (Avatar, Badge, Navigation/Mobile из эксперимента) — их цвета сейчас захардкожены. Для привязки нужно:

1. Через `get_metadata` получить структуру каждого
2. Через `use_figma` пройтись по их fills и заменить SOLID color на VARIABLE_ALIAS

Это **рискованная операция** — спроси Дарью перед запуском:
> «Готов привязать существующие компоненты <список> к новым Variables. Это перепишет их заливки. Бэкап сделан?»

Если Дарья подтверждает — делай **по одному компоненту**, после каждого `get_metadata` для проверки.

Зафиксируй всё, что создано, по шаблону ниже.

### Шаг 8. Финальная передача

## Lessons learned

- **2026-05-18 —** `get_variable_defs` обнаружил, что Variables НЕТ, хотя в документации заявлено 9.
  - **Правило:** первый шаг REVIEW — `get_variable_defs`.

- **2026-05-18 —** Контрасты как «~21:1» (приблизительные).
  - **Правило:** точные значения через WebAIM.

- **2026-05-18 —** Заявлено 39 компонентов, реально ~15.
  - **Правило:** сверить «заявлено» vs «реально через MCP».

- **2026-05-20 —** `use_figma` работает на запись (Navigation/Mobile создан).
  - **Правило:** простые компоненты — через `use_figma`. Сложные variants — спецификация + плагин Variants. Бэкап обязателен.

- **2026-05-20 —** `<symbol>` в `get_metadata` — это нормальный тип для ComponentNode.
  - **Правило:** `<symbol>` = компонент. Не паниковать.

- **2026-05-21 —** Цель студии — копировать стиль с референсов, не давать общие рекомендации. v3 этого не покрывал.
  - **Правило:** в v5 — главный режим `create-from-extract`. DS строится на основе `03-moodboard-extracted.md`, не из общих принципов.
