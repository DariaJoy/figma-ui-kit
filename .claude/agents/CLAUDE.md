# .claude/agents/ — инструкции для агентов студии

Здесь живут «роли», которые Claude принимает по запросу. Каждый `.md` файл — это законченный системный промпт одного агента.

## Жёсткие правила этой папки

1. **Один агент = один файл.** Не объединять несколько ролей в один файл.
2. **Все файлы имеют YAML-фронтматтер** с полями `name` и `description`. Без них агент «мёртв» — Claude Code не сможет правильно его идентифицировать.
3. **Каждый агент содержит секцию `## Lessons learned`** в конце. Туда дописываются уроки по итогам реальных задач.
4. **Версионирование в заголовке агента** (например, «Агент-секретарь (v3)») и история версий внизу файла. Это код, к нему относимся как к коду.

## Структура файла агента

```markdown
---
name: kebab-case-name
description: Use this agent for ... (что делает + когда вызывать)
---

# Заголовок агента (vN)

> Краткая суть роли в одной-двух фразах (эпиграф).

## Твоя роль
- Что ты делаешь
- Что ты НЕ делаешь
- Когда работа выполнена

## Принципы

## Что НЕ делаешь

## Сценарий работы (по шагам)

## Шаблон выходного файла

## Lessons learned
- (записи)
```

## Гайдлайны Anthropic — основное

- **Одна ответственность на агента.** Не пихать несколько ролей.
- **`description` — это триггер делегирования.** Пиши конкретно: что делает + когда вызывать.
- **Тело файла — полноценный системный промпт.** Детализированный, с примерами и с тем, что НЕ делать.
- **Изолированный контекст.** Агент не видит основной диалог, нужно задавать весь контекст.
- **Версионируй.** Любая правка — как code review.

## Существующие агенты

| Файл | Назначение | Режимы |
|---|---|---|
| `secretary.md` | Входной агент, intake, маршрутизация | — |
| `brief-analyst.md` | Бриф клиента | create / review |
| `ux-researcher.md` | Персоны, сценарии, экраны | create / review |
| `moodboard-curator.md` | Характер, палитра, типографика | create / review |
| `design-system-architect.md` | Токены, компоненты UI-kit | create / review |

## Жизненный цикл агента

1. **Создание.** Новый агент — отдельный коммит «Создан агент `<name>`».
2. **Первый запуск.** На реальной задаче. Записать ощущения.
3. **Ревизия инструкции.** По итогам первого запуска — обновить инструкцию (v1 → v2).
4. **Lessons learned.** После каждой работы — урок в файл, если был инцидент / корректировка / находка.
5. **Версионирование.** В заголовке агента — текущая версия. Внизу — история версий.
