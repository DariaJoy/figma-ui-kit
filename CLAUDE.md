# Студия — мета-среда работы Дарьи с клиентскими проектами

Это корень студии. Внутри живут агенты, проекты клиентов, общие skill'ы. Каждая папка может иметь свой CLAUDE.md с локальными правилами.

## Архитектурный принцип

Построено по официальной модели Anthropic для агентских сред (Claude Code subagents + контекстная иерархия CLAUDE.md), адаптировано под нужды студии полного цикла:

- **Каждый агент = отдельный .md файл с инструкциями**. Запускается через явное указание роли: «Работай как `<имя>`».
- **CLAUDE.md по иерархии** — Claude Code автоматически подгружает CLAUDE.md из текущей рабочей директории и всех родительских.
- **MCP-серверы** (Figma) подключаются на уровне родительского процесса.

## Правила маршрутизации

1. **Определи целевого агента:**
   - «новый клиент» → `secretary`
   - «бриф» → `brief-analyst`
   - «персоны / сценарии» → `ux-researcher`
   - «характер / палитра» → `moodboard-curator`
   - «токены / компоненты» → `design-system-architect`

2. **Запуск через переключение ролей:**
   ```
   Работай как <имя>, читай инструкции из .claude/agents/<имя>.md,
   проект <slug>, режим <create | review>.
   ```

3. **Не дублируй данные.** Ссылайся: `[см. бриф](01-brief.md)`.

4. **Figma write через MCP — теперь возможен** (см. урок 2026-05-20). Через `use_figma` можно создавать компоненты, фреймы, тексты, прямоугольники с auto-layout, цветами, типографикой. Не для всех случаев, но возможно. См. SKILL `figma-mcp-connection`.

## MCP-доступ

- **Figma MCP** (`mcp__plugin__figma__figma__*`) — для `moodboard-curator`, `design-system-architect`, и будущего `layout-designer`. **Включая запись через `use_figma`**.
- **Web tools** (`web_search`, `web_fetch`) — для `brief-analyst` и `moodboard-curator`.

## Цикл обучения (Lessons learned)

> Заимствовано из meta-pp template Anthropic.

Каждый запуск задачи — материал для опыта. Ошибки, обходные пути, удачные решения, корректировки пользователя — превращать в правила.

### Где живут уроки

В каждом файле агента в конце есть секция `## Lessons learned`.

### Формат записи

```markdown
- **YYYY-MM-DD —** что случилось (1 строка).
  - **Почему:** причина (1 строка).
  - **Правило:** что делать в следующий раз (1 строка).
```

### Триггеры записи

1. Ошибка / откат
2. Корректировка пользователя
3. Нетривиальная находка
4. Повтор паттерна
5. Расхождение с гайдлайнами

### Где какой урок

- Про **агента** → в его `.md` файл
- Про **студию в целом** → в этот CLAUDE.md
- Про **проект** → в `projects/<slug>/CLAUDE.md`

## Lessons learned (мета-уровень)

> Уроки, относящиеся ко всей студии.

- **2026-05-15 —** Перед каждым экспериментом с MCP-записью в существующий Figma-файл — сохранять бэкап (File → Save local copy + облачная копия).
  - **Почему:** дешевле застраховаться, чем восстанавливать.
  - **Правило:** бэкап перед write-операциями.

- **2026-05-15 —** Не делать всех агентов сразу.
  - **Почему:** на первой версии трудно угадать, какие правила нужны.
  - **Правило:** один агент → запуск на реальной задаче → обновление инструкции → следующий.

- **2026-05-17 —** При перезапуске агента в той же сессии Claude Code модель часто переиспользует данные предыдущего запуска вместо реального вызова MCP.
  - **Почему:** оптимизация токенов, контекст-окно держит результаты прошлых tool calls.
  - **Правило:** для повторных запусков — НОВАЯ сессия Claude Code. Удалить предыдущий артефакт.

- **2026-05-18 —** Subagent'ы Claude Code (через `.claude/agents/*.md` как отдельные процессы) НЕ наследуют подключение к MCP-серверам.
  - **Почему:** MCP-серверы аутентифицируются в процессе родительского агента. Поле `tools:` фильтрует, но не создаёт сессию.
  - **Правило:** все Figma-операции — родительский агент. У нас агенты = роли через переключение, не настоящие Claude Code subagents.

- **2026-05-20 — КРИТИЧЕСКИЙ ПЕРЕСМОТР ПРАВИЛ ⚠️**: Figma MCP **умеет писать в существующий файл** через инструмент `mcp__plugin__figma__figma__use_figma`. Эксперимент 2026-05-20 успешно создал компонент Navigation/Mobile в существующем файле Практика: фрейм, Figma Component (через `figma.createComponent()`), текстовый слой со шрифтом Unbounded Bold 18px, иконку Hamburger с auto-layout, цвета `#070809` и `#C5EE5B`. **Все предыдущие утверждения «Figma MCP в основном read-only» неверны.**
  - **Почему:** `use_figma` выполняет произвольный JS через Figma Plugin API (все возможности любого Figma-плагина). Этот инструмент не был замечен в предварительной оценке возможностей. Я несколько раз отговаривал Дарью от эксперимента, утверждая «работать не будет» — это была ошибочная оценка с моей стороны.
  - **Правило:** теперь `design-system-architect` и будущий `layout-designer` могут не только давать спецификацию, но и **создавать компоненты в Figma напрямую** через `use_figma`. Однако с оговорками: (1) файл должен быть открыт в Figma Desktop, (2) скрипт атомарный — упал = ничего не создалось, лучше дробить на мини-операции, (3) для сложных вариативных компонентов нужен опыт работы с Plugin API, (4) Figma Variables через MCP в существующей DS — рискованно, безопаснее через Tokens Studio. См. подробности в `.claude/skills/figma-mcp-connection/SKILL.md`, раздел 5.

## Что НЕ делать

- Не создавать новых агентов без необходимости.
- Не редактировать чужие проекты без понимания контекста.
- Не складывать «общие утилиты» в корень.
- ~~Не пытаться заставить Figma MCP писать сложные компоненты — её write-возможности сейчас ограничены.~~ — **отменено уроком 2026-05-20**, write через `use_figma` работает. Ограничения теперь конкретные и описаны в SKILL `figma-mcp-connection`.
