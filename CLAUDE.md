# Студия — мета-среда работы Дарьи с клиентскими проектами

Это корень студии. Внутри живут агенты, проекты клиентов, общие skill'ы. Каждая папка может иметь свой CLAUDE.md с локальными правилами.

## Архитектурный принцип

Построено по официальной модели Anthropic для агентских сред (Claude Code subagents + контекстная иерархия CLAUDE.md), адаптировано под нужды студии полного цикла:

- **Каждый агент = отдельный .md файл с инструкциями**. Запускается через явное указание роли: «Работай как `<имя>`».
- **CLAUDE.md по иерархии** — Claude Code автоматически подгружает CLAUDE.md из текущей рабочей директории и всех родительских. Поэтому правила нужного уровня всегда под рукой.
- **MCP-серверы** (Figma) подключаются на уровне родительского процесса.

## Правила маршрутизации задач

1. **Определи целевого агента** по содержанию запроса:
   - «новый клиент / разобрать что есть» → `secretary`
   - «разобрать или собрать бриф» → `brief-analyst`
   - «персоны / сценарии / экраны» → `ux-researcher`
   - «характер / референсы / палитра» → `moodboard-curator`
   - «токены / компоненты / UI-kit» → `design-system-architect`

2. **Все агенты работают через переключение ролей**, не как subagents. Запуск:
   ```
   Работай как <имя-агента>, читай инструкции из .claude/agents/<имя>.md,
   проект <slug>, режим <create | review>.
   ```

3. **Не дублируй данные между файлами.** Ссылайся: `[см. бриф](01-brief.md)`.

4. **Жёсткое правило по Figma MCP:** если агент не может выполнить write-операцию в Figma — он даёт спецификацию, Дарья рисует. Не пытаться обходить через создание HTML, генеративных картинок и т.п.

## MCP-доступ

- **Figma MCP** (`mcp__plugin__figma__figma__*`) — нужен `moodboard-curator`, `design-system-architect`, и будущему `layout-designer`. Подключение — через skill `figma-mcp-connection` (если будет создан).
- **Web tools** (`web_search`, `web_fetch`) — нужны `brief-analyst` (веб-разведка, конкуренты), `moodboard-curator` (поиск референсов студий).

## Цикл обучения (Lessons learned)

> Заимствовано из meta-pp template Anthropic. Самая ценная находка из чужого опыта.

Каждый запуск задачи — материал для опыта. Ошибки, обходные пути, удачные решения, корректировки пользователя — превращать в правила, чтобы не повторять.

### Где живут уроки

В каждом файле агента в конце есть секция `## Lessons learned`. Когда агент вызывается — он читает свой файл целиком, включая уроки.

### Формат записи

Три строки:
```markdown
- **YYYY-MM-DD —** что случилось (1 строка).
  - **Почему:** причина (1 строка).
  - **Правило:** что делать в следующий раз (1 строка).
```

### Триггеры записи урока

1. **Ошибка / откат.** Что-то пошло не так — урок.
2. **Корректировка пользователя.** Дарья поправила («не так, а вот так») — урок обязателен.
3. **Нетривиальная находка.** Найден неочевидный путь — урок.
4. **Повтор паттерна.** Похожая ситуация второй раз — кодифицировать.
5. **Расхождение с гайдлайнами.** Если паттерн Anthropic не подходит — урок в этот CLAUDE.md.

### Где какой урок

- Урок про **конкретного агента** → в его `.md` файл, секция `## Lessons learned`
- Урок про **процесс студии в целом** → в этот CLAUDE.md, раздел «Lessons learned (мета-уровень)»
- Урок про **конкретный проект** → в `projects/<slug>/CLAUDE.md`

## Lessons learned (мета-уровень)

> Уроки, относящиеся ко всей студии (не к конкретному агенту).

- **2026-05-15 —** Перед каждым новым клиентским проектом — сохранять бэкап Figma-файла (File → Save local copy + облачная копия).
  - **Почему:** Figma MCP сейчас в основном read-only, но эксперименты с write могут (в перспективе) затронуть файл. Дешевле застраховаться, чем восстанавливать.
  - **Правило:** бэкап перед любым экспериментом с MCP-записью в существующий файл.

- **2026-05-15 —** Не делать всех агентов сразу. Каждый создаётся, тестируется на реальном проекте, потом следующий.
  - **Почему:** на первой версии трудно угадать, какие правила реально нужны. Без реального запуска инструкции выглядят разумно, но при работе вскрываются пробелы.
  - **Правило:** один агент → запуск на реальной задаче → обновление инструкции по итогам → следующий агент.

- **2026-05-17 —** При перезапуске агента в той же сессии Claude Code модель часто переиспользует данные из предыдущего запуска вместо реального вызова MCP.
  - **Почему:** оптимизация токенов. Контекст-окно держит результаты прошлых tool calls, модели «кажется», что она уже всё знает.
  - **Правило:** для повторных запусков — НОВАЯ сессия Claude Code. Удалить или переименовать предыдущий артефакт (например, старый `00-intake.md`). В инструкциях агентов явно прописано «не переиспользуй старое».

- **2026-05-18 —** **Subagent'ы Claude Code (через `.claude/agents/*.md` как отдельные процессы) НЕ наследуют подключение к MCP-серверам.**
  - **Почему:** MCP-серверы аутентифицируются в процессе родительского агента. Subagent запускается в изолированном контексте без проброшенного MCP-подключения. Поле `tools:` во фронтматтере subagent'а только фильтрует список тулзов, но не создаёт MCP-сессию.
  - **Правило:** все Figma-операции исполняет родительский агент. У нас «агенты» реализованы как роли через переключение, не как настоящие Claude Code subagents — это и работает. Не переходить на настоящие subagents без необходимости.
  - **Источник:** lesson 2026-05-20 из meta-pp template (внешнего источника).

## Что НЕ делать

- Не создавать новых агентов без явной необходимости. Каждый агент = ответственность за поддержку.
- Не редактировать чужие проекты в `projects/` без понимания контекста.
- Не складывать «общие утилиты» в корень студии без структуры.
- Не пытаться заставить Figma MCP писать сложные компоненты — её write-возможности сейчас ограничены.
